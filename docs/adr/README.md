# Architecture Decision Records (ADRs)

Abbreviations used on this page include architecture decision record (ADR) and architecture decision records (ADRs), large language model (LLM) and large language models (LLMs), abstract syntax tree (AST), Model Context Protocol (MCP), command-line interface (CLI), language server protocol (LSP) and language server protocols (LSPs), concrete syntax tree (CST), identifier (ID), JavaScript Object Notation (JSON), remote procedure call (RPC), JavaScript Object Notation Remote Procedure Call (JSON-RPC), Language Server Protocol-Model Context Protocol (LSP-MCP), Java Development Tools (JDT), language server (LS), Unicode Transformation Format (UTF), Haskell Language Server (HLS), and Project Object Model (POM).

This directory contains records of all foundational architectural decisions, system invariants, and constraints for `semedit`.

To preserve the LLM context budget during development, consult this index first and view individual ADR files only when you need detailed context on a specific decision.

Before creating an ADR, check whether an existing record already covers the decision and update it when the scope matches. Create a new ADR only for a distinct architectural decision; do not split a continuing decision into additional records merely because it has new consequences or implementation details.

## Architectural Summary

`semedit` is a Go-native broker for deterministic, intent-driven editing: agents describe a semantic operation, while local AST and language-server tooling performs the mechanical transformation and reports diagnostics ([ADR-0001](0001-intent-driven-orchestration.md), [ADR-0002](0002-dual-engine-architecture.md), [ADR-0003](0003-symbol-based-addressing.md), [ADR-0004](0004-staged-execution-and-diagnostic-feedback.md)). Every MCP semantic operation is also available through the CLI; ingress remains separate from backend execution, and public interfaces, batch dispatch, and capability documentation derive from a typed operation registry ([ADR-0006](0006-dual-interface-delivery-and-agent-skills.md) through [ADR-0009](0009-mcp-coexistence-and-tool-scoping.md), [ADR-0014](0014-cobra-cli-framework.md), [ADR-0034](0034-central-operation-registry.md)).

Mutation is deliberately controlled: writes are atomic and cache-coherent; edits may remain applied with diagnostics; snapshots provide explicit, conflict-checked undo; and batches operate directly on the supplied workspace rather than providing embedded isolation ([ADR-0010](0010-disk-synchronization-and-cache-invalidation.md), [ADR-0018](0018-transactional-snapshots-and-undo.md), [ADR-0032](0032-direct-and-isolated-batch-execution.md)). Go AST operations validate input before mutation and preserve idiomatic declaration layout, access, and placement ([ADR-0011](0011-ast-declaration-insertion-and-import-management.md), [ADR-0012](0012-access-modifiers-and-section-placement.md), [ADR-0016](0016-replace-body-scaffold-insert-case-batch.md), [ADR-0019](0019-intent-driven-declaration-roles-and-statement-anchors.md)). Go exact-node removal complements insertion with comment-aware declaration and switch-case deletion; safe deletion remains on the same operation and is limited to unexported standalone constants with a complete module source scan ([ADR-0057](0057-exact-go-node-removal-and-safe-delete.md)).

The implementation remains exclusively Go and avoids unapproved workspace-manifest changes and runtime bootstrapping. External language servers use a language-neutral, bounded transport ([ADR-0005](0005-workspace-manifest-safety-and-monorepo-scoping.md), [ADR-0020](0020-exclusive-golang-runtime-and-tooling-ecosystem.md), [ADR-0021](0021-language-backend-service-boundary.md), [ADR-0022](0022-bounded-lsp-transport.md)). Scala and Haskell offer only tightly constrained trusted lookup; Kotlin adds trusted selected-file lookup and diagnostics; Rust offers lookup plus validated, selected-file rename; Java additionally has explicit Maven import, selected-file verification, and fixed trusted Maven test actions ([ADR-0024](0024-rust-file-scoped-lookup-backend.md) through [ADR-0037](0037-java-bounded-maven-actions.md)).

Errors use typed sentinels and location-aware records. Executable examples generate documentation, and CLI txtar contracts primarily cover public behavior while reporting all independent assertion failures ([ADR-0013](0013-sentinel-errors-in-go.md), [ADR-0015](0015-mkdocs-material-documentation.md), [ADR-0028](0028-cross-language-cli-txtar-coverage.md), [ADR-0033](0033-exhaustive-assertion-reporting.md)). Development-only live reload remains explicit and opt-in ([ADR-0017](0017-in-tree-live-reload.md)).

Benchmarking treats task and steering choices as explicit experiment conditions, preserves technical provenance without fragmenting comparisons, and publishes only oracle-evaluated observations with ordered tool outcome telemetry ([ADR-0038](0038-benchmark-experiment-conditions-and-provenance.md), [ADR-0039](0039-benchmark-result-validity-and-tool-telemetry.md)). Fixtures keep prompts visible while keeping acceptance oracles hidden until the agent exits ([ADR-0040](0040-benchmark-fixture-and-oracle-isolation.md)). MCP execution uses an explicit project-local Go state boundary, validates it before tool discovery, and advertises machine-readable structured tool results ([ADR-0041](0041-mcp-runtime-configuration-and-project-local-go-state.md), [ADR-0042](0042-mcp-structured-tool-output-schemas.md)). Feedback reporting is a separate MCP support utility that returns a privacy-guided draft for user review and manual issue posting, without automatic submission ([ADR-0045](0045-structured-mcp-feedback-reports.md)). Construct-level AST replacement and collision-guarded declaration updates provide focused mutations for loops, constants, and variables ([ADR-0046](0046-construct-level-ast-replacement-and-declarative-updates.md)). Go extraction has a bounded, fail-closed contract for contiguous direct calls with explicit parameter flow and one supported returned local ([ADR-0056](0056-go-call-statement-extraction.md)). Tool ingress applies Postel's robustness principle (lenient in, precise out) across scope paths, synonyms, and delimiters while guaranteeing canonical output contracts ([ADR-0065](0065-lenient-in-precise-out-input-resolution.md)).

## Active Requirements (Invariants)

These stable-ID requirements summarize accepted decisions. The linked ADRs define their scope and exceptions. Keep each requirement testable and maintain an explicit test link as described in the [README testing policy](../../README.md#requirements-and-invariant-tests).

* **REQ-001 — Semantic intent.** Agents MUST express code changes as semantic intent when a registered operation covers the task; the host engine MUST perform syntax-aware transformations. ([ADR-0001](0001-intent-driven-orchestration.md), [ADR-0002](0002-dual-engine-architecture.md), [ADR-0007](0007-semantic-mcp-tool-naming-and-descriptions.md))
* **REQ-002 — Public operation surfaces.** Every public operation MUST be available through the CLI and registry dispatch; MCP discovery MAY filter registered operations by catalog profile and explicit variant patterns. The typed registry MUST define dispatch and advertised capabilities. ([ADR-0006](0006-dual-interface-delivery-and-agent-skills.md), [ADR-0009](0009-mcp-coexistence-and-tool-scoping.md), [ADR-0034](0034-central-operation-registry.md), [ADR-0053](0053-whole-construct-and-body-replacement.md))
* **REQ-003 — Backend boundaries.** Language backends MUST own language-specific semantic policy; shared services MUST select registered capabilities without weakening backend validation. ([ADR-0021](0021-language-backend-service-boundary.md), [ADR-0029](0029-backend-owned-trusted-lsp-rename-boundary.md))
* **REQ-004 — Mutation safety.** Writes MUST be validated before publication, atomic on disk, and coherent with tool caches; applied edits with diagnostics MUST remain explicit rather than being silently rolled back. ([ADR-0004](0004-staged-execution-and-diagnostic-feedback.md), [ADR-0010](0010-disk-synchronization-and-cache-invalidation.md), [ADR-0018](0018-transactional-snapshots-and-undo.md), [ADR-0032](0032-direct-and-isolated-batch-execution.md))
* **REQ-005 — External tool boundaries.** External language tools MUST run only within declared trust, scope, and lifecycle boundaries; unsupported or incomplete capability coverage MUST be reported explicitly. ([ADR-0005](0005-workspace-manifest-safety-and-monorepo-scoping.md), [ADR-0022](0022-bounded-lsp-transport.md), [ADR-0032](0032-direct-and-isolated-batch-execution.md), [ADR-0041](0041-mcp-runtime-configuration-and-project-local-go-state.md), [ADR-0048](0048-bash-and-makefile-read-only-backends.md), [ADR-0054](0054-project-verification-hooks.md))
* **REQ-006 — Public behavior coverage.** Every advertised language-operation pair MUST have comparable CLI txtar contract coverage unless its capability registry explicitly marks the operation unsupported. ([ADR-0028](0028-cross-language-cli-txtar-coverage.md))
* **REQ-007 — Project-owned quality policy.** Project formatting, ordering, lint, and verification policy SHOULD remain project-owned and MUST run only through explicit supported hooks or recognized project signals. ([ADR-0054](0054-project-verification-hooks.md))
* **REQ-008 — Benchmark evidence.** Benchmarks MUST preserve task conditions, oracle outcomes, and per-run evidence so comparisons remain reproducible and interpretable. ([ADR-0038](0038-benchmark-experiment-conditions-and-provenance.md), [ADR-0039](0039-benchmark-result-validity-and-tool-telemetry.md), [ADR-0040](0040-benchmark-fixture-and-oracle-isolation.md), [ADR-0043](0043-benchmark-run-aggregation-and-best-case-publication.md), [ADR-0050](0050-benchmark-planning-sessions-and-arm-policy.md))
