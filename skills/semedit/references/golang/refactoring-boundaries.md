# Go Refactoring Boundaries

Read this reference when a Go refactoring needs exact eligibility or refusal rules. For common operation selection and parameters, start with the [primary tool guide](../../SKILL.md#choose-the-operation-by-intent) and [Go language guide](../golang.md).

## Extract one value

Use `refactor_extract_value` with `kind: "variable"` to extract an exact argument of a direct call statement; the RHS of a simple `=` assignment, single-name `:=` declaration, or single-spec local `var` declaration with one named target and one RHS; one whole expression from a return in an owner with exactly one result field, either unnamed or named with one nonblank identifier; or the complete condition of an `if` without an init clause. A named result is assigned by the original return, so deferred functions observe the same result value. Multiple result fields, blank or multiply named result fields, and naked returns refuse. Assignment, declaration, return, and condition locals stay immediately before their selected statement in that same branch, loop, clause, or nested block; function-literal bodies are outside the owner's candidates. Condition extraction requires a side-effect-free expression with a resolved typed input; it does not extract one operand or move a local across the `if` boundary. Grouped `var` declarations, multi-name or multi-value var specs, multi-name short declarations, compound or tuple assignments, and non-identifier targets refuse. If an expression matches multiple supported statements, use `semantic_inspect_construct` to select its `construct_path`; whenever you supply a path, pass its matching `expected_revision`. Extraction preserves the selected expression's compiler-resolved type and evaluates it at its original point. For a complete `if` condition, Go permits its untyped Boolean result to default to `bool` in the generated local; other resolved types must remain identical. Return extraction also preserves defer order. Untyped-only expressions and unsupported expression forms refuse. A supported expression may still panic, but its evaluation remains at the same point in the owner. For calls, every sibling argument must be a compiler-proven constant, resolved predeclared `nil`, or a bare scalar owner input; this ordering rule applies to first arguments too. A chosen call may coalesce all exact matching arguments into one local only when the repeated expression uses typed scalar owner inputs and compiler constants, every occurrence has the same resolved type, and no input is address-escaped explicitly or through an implicit pointer-receiver method selection, or captured by a nested function. Select a call with `construct_path` plus its matching `expected_revision` when several direct statements match. To share one evaluation across calls, select an inclusive range with `construct_path`, `end_construct_path`, and the same `expected_revision`; every statement in the range must be a matching direct call, and all selected expressions must have stable typed scalar inputs and the same resolved type. Any intervening non-call or nonmatching call refuses. To share one evaluation across assignments, select an inclusive direct-statement range with `construct_path`, `end_construct_path`, and the same `expected_revision`. The range must contain at least two contiguous one-target `=` assignments in one owner block, each with the exact same RHS discriminator. Each target must be an existing owner-local distinct from all RHS inputs; the RHS must be a stable typed scalar expression over typed scalar owner inputs and compiler constants, with one identical resolved type across the range. Inputs cannot be written, address-escaped, or captured in the owner. Calls, declarations, nested/control-flow ranges, nonmatching statements, and short, compound, tuple, or non-identifier assignments refuse. Exact source preservation is checked before formatting, then the candidate is reparsed and type-checked. Other expressions remain subject to the single-expression purity and type checks. Generic and variadic callees and variadic expansion refuse. Go resolves and compares expression types in the original and candidate package; assignment, var initializer, return, and condition expressions must contain a typed input, and all forms refuse side effects, comments, ambiguous matches, and stale selections. Direct calls require same-file unshadowed package functions.

For `kind: "constant"`, one unique exact discriminator match retains the existing behavior. To replace a subset of duplicate exact matches, supply strictly increasing zero-based `occurrence_indices` in source order and the current `expected_revision`; indices count exact expression matches in the selected owner, excluding nested function literals. The selected expressions must share one resolved type and exact value, and the candidate package must resolve every replacement to the generated package constant. Omitted indices never mean replace-all. Cross-owner or cross-file selection is unsupported.

## Extract callable regions

Use `refactor_extract_callable` under [ADR-0056](../../../../docs/adr/0056-go-call-statement-extraction.md) to extract supported call, assignment, branch, loop, and switch-case regions into a helper. A nested selection uses revision-bound inspected paths and must stay in one lexical block; the call remains at the same branch or loop execution point. Within one expression-switch case/default body, a contiguous direct-call range or one direct simple `=` assignment is supported. The assignment may target a pre-existing owner local or named owner parameter, including a method parameter, when read after the whole switch; the helper result is assigned back at the same clause location. The receiver remains unsupported. Path traversal does not descend into nested case statements. Other assignments, declarations, non-local targets, targets without a post-switch read, ranges crossing cases, type-switch cases, and select clauses refuse. A complete direct-owner `if/else` requires a pure typed scalar condition over scalar owner inputs and constants and call-only branches, with no init clause. Nested control flow, writes, declarations, exits, non-scalar owner inputs, and unsafe aliases refuse.

ADR-0056 groups the supported loop forms: counted loops; string, integer, and receive-capable channel ranges; direct local/parameter map ranges with scalar key and element types; direct local/parameter slice ranges; two-index slice expressions (`items[:]`, `items[lo:]`, `items[:hi]`, `items[lo:hi]`); supported full-slice expressions (`items[low:high:max]`, `items[:high:max]`); and direct same-package scalar-slice factory ranges. Slice bases and bounds must meet the nameability and purity checks; preserve the original range expression so Go retains index origin, captured length, backing-array identity, capacity-based full-slice bounds, evaluation order, and panic timing. All operands must appear only in their allowed range position, and the helper receives the same typed values. Unsupported operands, types, selected-body uses, effects, nested control flow, owner writes, labels, and statement forms refuse. Iteration variables stay local to the helper.

Select with inclusive `start_line` and `end_line`, or use inspected `construct_path` and optional inclusive `end_construct_path` endpoints with the current selected-file `expected_revision`. Paths may descend through explicit blocks, if/else bodies, counted-loop bodies, and range-loop bodies. Expression-switch case/default paths select contiguous direct-call ranges or one direct simple assignment to a pre-existing owner local or named parameter and read after the whole switch; the helper result is assigned back at the original clause location. Path traversal does not descend into nested case statements. Other assignments, declarations, receiver writes, targets without a post-switch read, cross-case ranges, type-switch and select clause paths refuse. Go object identity and `go/types` determine live-ins and live-outs across straight-line regions, including mixed declarations, tuple assignments, and writes to existing locals. Package-visible named scalar, struct, pointer, and interface types are supported when they can appear in the helper signature. Plain assignment targets are writes, not reads; compound assignments and increment/decrement are refused in straight-line extraction. Later writes preserve output declarations, and write-only owner bindings receive a blank use when required. Ordinary comments move with the selected source only when every comment group inside the owner body lies wholly within the selected range; directives and comments outside the selected range refuse under ADR-0056. A comment following the owner's closing brace remains attached to it. Internal and external `_test.go` targets are validated against the applicable test variant. Function-local named types, type parameters, captures, address escapes, and unproven aliasing remain refusals.

For `kind: "method"`, the owner receiver stays on the extracted helper. Method helper names must be unexported so extraction cannot add a public interface implementation outside the workspace. The engine also refuses names already present in the value or pointer receiver member sets, including promoted methods and fields, and names used by package interfaces.

## Inline values and callables

For ADR-0091's computed expression case, the immediate call target must resolve to a declared function or builtin; a function-valued local or parameter refuses. Candidate validation preserves the resolved call-target identity alongside the argument type and initializer inputs.

Under [ADR-0091](../../../../docs/adr/0091-bounded-go-computed-local-inline.md), a pure scalar computed local may be inlined only when its sole resolved use is the complete expression of the immediately following statement in the same owner block. Supported destinations are direct return; one-argument direct calls to declared functions or builtins; simple assignment to a distinct existing identifier; one-name `:=`; one-name, one-value ungrouped local `var`; complete `if` condition or expression-switch tag without init; and sole arguments to direct `defer` or `go` calls. Candidate analysis preserves initializer inputs, binding identities, types, constant values, callee and destination identity, and evaluation timing. The `if` condition must remain Boolean; a switch tag must be explicit. Defer arguments retain evaluation at registration, while `go` arguments evaluate before goroutine start. Methods, selectors, indirect targets, multiple/variadic arguments, partial expressions, grouped or multi-value declarations, comments, intervening statements, extra uses, and unsupported initializers refuse unchanged.

Use `refactor_inline_value` for supported basic-literal locals later in the same lexical block when the binding is not reassigned and no control-flow boundary separates declaration from use. Unrelated intervening statements may remain. For computed scalar locals, follow the adjacent-use destinations in ADR-0091 above. Computed expressions admit only scalar literals, owner-local scalar variables or constants, parentheses, and pure unary or binary operators; candidate overlay checks preserve input bindings, types, constant values, and expression type. Calls in initializers, selectors, indexing, pointer/channel operations, conversions, mutable globals, unsupported operators, comments/directives, additional or indirect uses, and unproven test-file owners refuse.

ADR-0087 also permits one inferred `:=` binding initialized by a keyed composite literal of a same-package, nongeneric named struct. Every declared field, including omitted fields, must be a scalar Go basic type; every supplied value must be a basic literal or the resolved predeclared `true`/`false`. The binding must have exactly one object-identity-resolved use as the sole expression in the immediately following direct `return`, and its owner must have one unnamed result. The candidate return type is checked against compiler type information from the same source-buffer overlay before publication. The transformation preserves the original type spelling and literal bytes; standalone output retains that spelling, while batch finalization applies normal Go formatting and can normalize it.

Explicit local types, positional or imported/generic literals, defined scalar or embedded fields, nonliteral field values, aliases, parenthesized field values, comments/directives in the removed region, multiple or indirect uses, and other return shapes refuse. The implementation fails closed for selected `*_test.go` owners until their compiler variant is proven. See [ADR-0087](../../../../docs/adr/0087-bounded-go-struct-literal-inline-value.md) for the contract.

Use `refactor_inline_callable` for one selected zero-argument free-function call or concrete method call. The callee and caller may be in different files of the same active package. The ordinary single-call contract selects the call as the sole expression of a direct owner-level `return`. Under [ADR-0097](../../../../docs/adr/0097-bounded-go-multi-site-callable-inlining.md), a free function may instead use `call_site.occurrence_indices` to select at least two exact discriminator matches, in strictly increasing zero-based source order, bound to `call_site.expected_revision`. Each selected call must be the complete expression of a direct owner-level `return` or the complete RHS of a direct owner-level one-target `:=` or `=` assignment. The callee must be a same-package, non-generic, non-variadic free function with zero parameters and one direct basic literal return of a predeclared basic type. Every selected site is type-checked against the candidate package overlay before one atomic publication. Nested/control-flow contexts, overlapping/comment-boundary edits, malformed or stale selections, methods in multi-site mode, and all other unsupported shapes refuse. The single-call method form still requires a directly resolved method with one unnamed result and a direct identifier receiver naming a caller parameter, without implicit indirection; the caller must contain only that return. Calls on locals or package variables, interface values, embedded or promoted methods, method values, cross-package declarations, parameterized callees, and receiver expressions with side effects refuse. Active build-constrained variants outside the selected package file set refuse.
